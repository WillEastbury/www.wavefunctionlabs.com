How a Transformer Produces One Token

You type "The capital of France is" — the model runs this pipeline and out comes " Paris".

What you type becomes numbers
“The capital of France is”
state: raw text, 26 characters
↓
Tokenizer

Split the sentence into small reusable pieces, then swap each piece for a dictionary number.

→ ch2
state: ["The", " capital", " of", " France", " is"] → [450, 3007, 310, 3444, 338]
5 integer IDs. The text is gone.
↓
Embedding Lookup

Use each ID as a row number into a giant table. Copy out that row — 4,096 numbers per token.

→ ch3
state: 5 rows × 4,096 numbers each = 20,480 floats
row 0: [-0.22, 0.74, 0.04, -0.16, …] ← "The"
row 1: [ 0.52, -0.10, 0.27, 0.04, …] ← " capital"
row 2: [-0.09, 0.41, -0.33, 0.21, …] ← " of"
row 3: [ 0.67, -0.04, 0.18, -0.30, …] ← " France"
row 4: [ 0.11, 0.56, -0.09, 0.38, …] ← " is"
↓
Position Stamp

Rotate pairs of numbers based on position so the model knows word order. Without this, shuffling the rows would look the same.

→ ch4
state: same 5 × 4,096 grid, but each row now has a unique rotational fingerprint for positions 0–4
The thinking loop
× 32 Layers
↓
Normalise

Rescale numbers so nothing drifts too large or too small between layers.

→ ch7
state: each row rescaled to stable magnitude (RMS = 1.0)
↓
Attention

Each word looks back at all earlier words and blends in whatever seems relevant. Three projections decide: "what do I need?", "what do I offer?", "what do I contribute?"

→ ch6
state (token 4, " is"):
looked back → "France" scored 0.42, "capital" scored 0.31, "The" scored 0.08 …
blended result: a new row that mixes in context from the whole sentence
↓
+ Add Back

Don't throw away what you already knew. Add the new update on top of the old state.

→ ch5
state: original row + attention update = richer row
↓
Normalise

Rescale again before the next transformation.

→ ch7
↓
Feed-Forward

Each row processed individually: expand to 11,008 numbers, apply a filter, compress back to 4,096. Patterns become decisions.

→ ch8
state: 4,096 → expand to 11,008 → filter → back to 4,096 (sharper, more refined)
↓
+ Add Back

Merge update into running state. Hand the richer rows to the next layer.

→ ch5
after all 32 layers: token 4 (" is") has been refined 32 times.
It no longer means "is" — it means "the-word-after-'The-capital-of-France-is' in a context expecting a city name."
Choosing the next token
↓
Final Normalise

One last rescale before scoring.

→ ch7
↓
Score Every Token in the Dictionary

Compare the finished row against all ~128,000 known words. Each word gets one score — higher means "better fit here."

→ ch9
scores (top 5 of 128,000):
" Paris"   → 18.4
" France"  → 15.8
" French"  → 13.9
" Lyon"    → 11.7
" London"  → 11.1
… 127,995 more rows scored lower
↓
Pick One

Turn scores into probabilities. Apply temperature, top-k, top-p. Sample one winner.

→ ch10
probabilities after softmax:
" Paris" → 89.1%  |  " France" → 6.7%  |  " French" → 1.9%  |  …
sampled: " Paris" ✓
↓
" Paris"
Token emitted. One token done.

Prefill vs Decode

Prefill (first pass)

Process all 5 input tokens at once. Fill the memory cache with reusable results. Heavy work — but only done once per prompt.

Decode (every pass after)

Generate one token at a time. Reuse the cached history for the old tokens. Only compute new results for the freshest token.

why decode is slower than you'd expect: even though only 1 token is new, the model still reads all 7 billion parameters from memory every step. The bottleneck is memory bandwidth, not compute.
